# MaaS 文本生成模型双用例对比设计

## 目标

提供一个可由 MySQL `source` 执行的真实 MaaS 对比脚本，对已配置的六个
`TEXT_GENERATION` 模型执行相同的两个业务用例，并输出可人工评审的模型结果与耗时。

## 范围

- 对比模型：`huawei/glm-5.2`、`huawei/kimi-k2.6`、`huawei/deepseek-v4-pro`、
  `huawei/deepseek-v4-flash`、`huawei/openpangu-2.0-pro`、
  `huawei/openpangu-2.0-flash`。
- 用例一：慢 SQL/DBA 诊断。输入固定的 SQL 摘要、执行计划、耗时和扫描行数；要求按
  原因、证据、风险、建议输出，且不生成自动修复 SQL。
- 用例二：订单经营数据分析。输入固定的当月、上月订单和收入指标；要求概述变化、识别
  异常或风险，并提出可验证的业务分析方向。
- 每次调用使用 `max_output_tokens=512`、`timeout_ms=60000`，共 12 次真实 MaaS 调用。

## 脚本行为

1. 脚本不注册模型、不读取或输出 API Key；调用者事先配置模型并具备 `AI_INVOKE`。
2. 脚本将模型名和用例定义写入当前会话的临时表，按模型/用例逐条调用
   `AI_ANALYZE()`。
3. 每条调用记录开始/结束时间、结果文本、结果字符数或脱敏错误信息。调用完成后按
   用例、模型顺序输出完整结果和耗时，便于人工比较。
4. 单条调用失败不阻止后续模型/用例继续执行；最终摘要显示成功和失败数量。
5. 无论成功或失败，脚本在最后删除临时表。它不比较结果文本的精确内容，因为模型输出
   天然非确定；人工按中文质量、输入证据引用、风险识别和建议可验证性进行评审。

## 边界与安全

- 此脚本会产生 MaaS 调用与费用；只应在已获授权的开发/验证环境运行。
- 模型回答、业务测试输入和耗时会显示在 mysql 客户端，不写入仓库、系统表或审计外的
  文件；审计由服务端既有机制处理。
- 该脚本不作为默认 MTR 用例，MTR 保持离线、无密钥、无费用。

## 验收

- 六个已配置模型均尝试两个用例；输出包含模型名、用例名、耗时、完整结果或脱敏错误。
- 无 API Key、Authorization 或模型配置明文写入脚本、结果文件或仓库。
- 临时表在结束后不存在；主工作区现有待提交脚本不被改动。
